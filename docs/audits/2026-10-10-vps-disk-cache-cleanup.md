# VPS disk warning cleanup — 10 October 2026

## Cause

The disk warning threshold is 80% and the disk check runs every 15 minutes. As long as usage stays over the threshold, the alert can be raised again after its six-hour throttle window. The reported 80.6% was real usage on the filesystem containing `/data/storage`, not a false reading. Docker reported 31.02 GB of build cache (27.52 GB initially reclaimable) and 21.15 GB of reclaimable old images. Repeated deployments had accumulated build cache.

## Action

- Pruned Docker build cache older than 72 hours, then all remaining unused build cache. This cache can be regenerated by future builds.
- Kept all 81 Docker images, including rollback tags; did not prune images, containers or volumes.
- Installed `oxeio-docker-cache-prune.service` and `.timer` under `/etc/systemd/system`. The timer runs daily at 21:30 UTC / 03:30 Asia/Dhaka, with up to 15 minutes of randomized delay, and caps build cache at 8 GB. `Persistent=true` catches up after VPS downtime. The service only runs `docker builder prune --all --force --max-used-space 8GB`.
- Unit source and before/after logs: `/opt/oxeio-releases/disk-housekeeping-20261010`. Local unit copies: `.release-salary/oxeio-docker-cache-prune.service` and `.release-salary/oxeio-docker-cache-prune.timer`.

## Verified outcome

- `/dev/vda1`: 80% used (16.9 GB available) before; 47% used (43.7 GB available by byte-based `df`, about 41 GiB in `df -h`) after.
- Docker build cache: 31.02 GB before; 0 B after the one-time cleanup. Future builds will repopulate it up to the maintenance cap.
- The same filesystem mounted at `/data/storage` inside `oxeio-api` showed 47% used.
- The timer is enabled and active; `systemd-analyze verify` passed and a manual service run returned success.
- `oxeio-web`, `oxeio-api`, and `oxeio-postgres` retained their container IDs and remained healthy. Public health reported `ok`, DB `up`, build 478 / `edf0686`. No app deployment, database migration, or data deletion occurred.

Existing already-sent notifications cannot be recalled. The disk check should not issue another 80% warning while usage stays below 80%; monitor the daily cleanup timer and free-space trend.
