oXeio agent · tray

“Today's hours” — the one screen every staff member sees

This window is the whole transparency promise made visible: the number that decides someone's pay, on their own screen, without asking anyone. Right now it looks like a system dialog, and the most loaded number on it — 79:20 hours behind — is drawn in exactly the same weight as Queued: 0. The redesign below changes the treatment, not the rules.

Now, and proposed

Both at 1:1 — 400 px wide, the width TodayForm already asks for. Real numbers from the 11 August run.

The four states it has to hold

Every one of these already exists in TodayForm.PaintBody. The redesign has to survive all of them — including the one where the month is not known yet, which is the state a staff member sees for the first few seconds after every logon.

What changed, and why

Five changes. Each one is a rule the product already decided somewhere else and this window was not following.

It joins the product

OwnerDrawnForm paints with SystemColors.Window and SystemColors.GrayText, so the window inherits whatever Windows is wearing and carries no identity at all. It now uses the same tokens as the dashboard, and defaults to Midnight — because index.css sets color-scheme: dark as the product's default, not light dark.

The blue bar was not ours

ProgressColor fills the month bar with #4A6FA5, a blue that appears nowhere else in oXeio. The dashboard already settled this argument: a ring in progress is neutral ink, and only turns green when the target is met — because a red-ish “attention” ring burning on every working person's card all day makes the colour mean nothing within two days.

“79:20 behind” gets a picture

The number alone is an accusation with no scale. The meter now carries a tick at expected by today, so the gap is something you see before you read it — and the same glance also shows how much of the month is left to close it in.

It stays amber, never red. Red is reserved for “your data is not reaching the server”, which is the system's fault; being behind is not an incident.

State becomes a chip, not a row

Now: Working was the fourth row of a four-row list, all equal weight. It is the only line that changes minute to minute, so it moves up beside the figure it explains and gets the dot vocabulary the Live Board already uses — green working, amber idle, grey locked.

A sliver, not nothing

At 0:39 of 208 hours the fill is 0.3% — 1.1 px on a 360 px meter, which GDI rounds away to nothing. “I have worked a little” would look identical to “I have worked none”. The fill keeps a 3 px minimum whenever the ratio is above zero, and only a true zero draws empty.

Sync stops being prose

Three facts about the machine — Sync · Last sync · Queued — become three small monospace readouts on one line instead of three sentences in the middle of the window. The full explanation appears only when something is actually wrong, which is when a person needs a sentence rather than a label.

What deliberately did not change

These are load-bearing product decisions, not layout.

Still no buttons

Not a break button, not “claim time”, not a refresh. One control here is the first step of an approval workflow, and this system has no approvals.

Sync is shown when it is fine

Hiding it while healthy would mean the most reassuring fact — your hours arrived — is invisible exactly when it is true.

Both footnotes stay, in full

“Where did my time go” has to be answered before it is asked, or people assume the system is eating their hours. They are quieter now, not shorter.

“Pace (estimated)” keeps its word

When the server has not sent the exact figure, the label still says estimated — that word is the admission that we do not know this month's holidays.
